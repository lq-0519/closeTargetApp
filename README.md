# CloseTargetApp

一个给自己 MacBook 用的菜单栏小工具：在菜单栏放一个按钮，点击后可以选择睡眠、关机或重启。执行这些动作前，App 会先关闭配置好的目标应用。

## 功能

- 菜单栏按钮
- 自定义 App 图标
- 睡眠、关机、重启快捷入口
- 执行电源动作前强制退出指定应用，并确认全部退出后再继续
- 设置窗口中添加/移除目标应用
- 开机自启动开关
- 可在设置中调整关闭目标应用的最长等待时间（1–60 秒，默认 5 秒），应用提前退出则立即继续
- 软件电源操作及合盖睡眠前关闭 Wi-Fi 和蓝牙，正常唤醒或重新登录后打开
- 一个无线管理总开关，继承旧版本 Wi-Fi 功能的开启/关闭选择
- 独立保存两项恢复进度；失败时保留“恢复 Wi-Fi 和蓝牙”菜单入口
- 自动恢复两项无线后显示一条无声系统通知，可在设置中单独关闭
- 自动保存配置

## 无线与等待设置

总开关默认开启：软件睡眠、关机、重启按钮与合盖睡眠会关闭 Wi-Fi 和蓝牙。
开盖闲置自动睡眠、系统菜单睡眠不会创建无线关闭任务；合盖外接显示器继续工作也不触发。
合盖只管理无线设备，不强制退出目标应用；软件按钮仍先强制退出目标应用，确认全部退出后执行电源动作。
最长等待时间为 1–60 秒（默认 5 秒），提前退出则立即继续，超时取消本次按钮操作。

正常恢复要求亮屏事件及实时亮屏；合盖来源还要求已经开盖。后台 DarkWake 不恢复无线。
关机、重启通过现有登录项在登录后恢复，不保证登录前联网；启用总开关时注册登录项。
关闭总开关不创建新关闭任务，但仍完成本软件已关闭设备的待恢复任务。
第一次使用新增的蓝牙能力时需要允许系统蓝牙权限；软件启动或开启总开关时提前初始化，后续构建保持同一签名身份。

两个无线设备分别保存恢复进度，最多重试三轮；一个失败不会阻止另一个恢复。
软件操作失败还原原始开关状态，正常唤醒按要求打开两者，即使操作前原本关闭。
恢复记录原子保存在 `~/Library/Application Support/CloseTargetApp/wifi-recovery.json`，兼容旧 Wi-Fi 记录，
旧记录的恢复不操作蓝牙。菜单可手动重试，退出应用前会尝试完成已有恢复。

空闲时只监听 IOKit 合盖、电源及 AppKit 屏幕事件，不扫描、不常驻轮询。
合盖关闭窗口最多八秒，超时继续系统睡眠，已关闭的设备保留恢复任务。
软件电源请求后三十秒仍未观察到睡眠会尝试回滚。

“无线恢复后通知”默认开启，首次使用需要允许系统通知权限。正常唤醒或重启登录后，
两项无线均自动恢复成功才显示“无线已恢复：Wi-Fi 和蓝牙已自动打开。”，每次任务一条且无声音。
手动恢复、失败回滚、部分恢复及旧 Wi-Fi 单项记录不发送；通知不表示网络或设备已连接。
通知使用 UserNotifications 本地提交，不联网或增加定时轮询；拒绝权限不影响无线恢复。

Wi-Fi 使用 CoreWLAN；蓝牙使用与 blueutil 相同的非公开 IOBluetooth 电源接口，后台调用并读回确认。
系统升级可能影响蓝牙接口兼容性，失败会明确显示。首次访问可能需要系统授权；
构建继续使用原固定签名和 Bundle ID，不重置现有权限。

## 图标

如果之后想替换 App 图标，可以替换 `Resources/AppIcon-source.png`，然后执行：

```bash
./scripts/generate_app_icon.sh
./scripts/build_app.sh
```

## 打包

```bash
chmod +x scripts/build_app.sh
./scripts/build_app.sh
```

打包完成后会生成：

```text
dist/CloseTargetApp.app
```

建议把它移动到 `/Applications` 后再开启「开机自启动」，这样 macOS 的登录项注册更稳定。

构建脚本会固定复用本机已有的长期代码签名身份，使重新构建后的 App 保持相同代码身份，
避免系统权限随每次编译产生的新二进制失效。如果在其他机器构建，需要通过
`CLOSE_TARGET_APP_SIGNING_IDENTITY` 指定该机器上的稳定代码签名身份。
本机继续使用 `com.local.CloseTargetApp` 和原有证书，不改 Bundle ID、不使用 ad-hoc 签名，也不重置系统权限。

## 使用

1. 打开 `dist/CloseTargetApp.app`。
2. 在菜单栏点击 `xmark.octagon` 图标。
3. 进入「设置...」，添加你想关闭的应用。
4. 回到菜单栏，点击「睡眠」「关机」或「重启」。
5. App 会先强制退出目标应用；确认全部退出后，才执行你选择的电源动作。
6. 如果需要，打开「开机自启动」。

## 测试建议

不需要把整个项目本地跑起来调试。可以按下面几步手动验收：

1. 执行打包脚本，确认生成 `dist/CloseTargetApp.app`。
2. 打开 App 后确认菜单栏出现按钮，Dock 中不出现常驻图标。
3. 在设置里添加一个无重要数据的测试应用，例如「备忘录」或「预览」。
4. 保存当前工作后，点击「睡眠」验证测试应用收到退出请求，电脑进入睡眠。
5. 关机和重启会真实执行系统动作，建议只在确认没有未保存内容时测试。
6. 切换「开机自启动」，若提示需要允许，到系统设置的登录项中确认状态。
