# CloseTargetApp

一个给 MacBook 使用的菜单栏小工具：在睡眠、关机或重启前，一键关闭配置好的应用，并管理 Wi-Fi 和蓝牙的关闭与恢复。

适合下班前需要退出编辑器、开发工具等应用的场景，减少逐个关闭的重复操作，也用于尝试减少合盖后因应用或无线设备活动带来的耗电、发热。实际节能效果取决于应用和系统状态。

## 主要功能

- 菜单栏提供睡眠、关机和重启入口。
- 在设置中添加或移除需要关闭的应用。
- 执行电源动作前强制退出目标应用，确认全部退出后再继续。
- 最长等待时间可设置为 1～60 秒，默认 5 秒；提前退出就立即继续，超时则取消按钮操作。
- 可在软件电源操作及合盖睡眠前关闭 Wi-Fi 和蓝牙。
- 正常亮屏唤醒或重新登录后恢复无线设备，失败时提供手动恢复入口。
- 可选的无声无线恢复通知。
- 支持登录自启动和自动保存配置。

工具会强制退出所选应用，使用前请保存这些应用中的工作。普通合盖仅管理无线设备，不强制退出目标应用。

## 使用方法

1. 启动应用，点击菜单栏图标，打开“设置…”。
2. 添加希望在电源动作前关闭的应用。
3. 按需设置最长等待时间、无线管理和恢复通知。
4. 保存工作后，从菜单选择“睡眠”“关机”或“重启”。
5. 应用确认目标进程全部退出后，执行对应的系统动作。

建议安装在 `/Applications/CloseTargetApp.app`，再开启登录自启动。

## Wi-Fi 和蓝牙管理

无线管理总开关默认开启。通过本工具的电源按钮或真正的合盖睡眠，会关闭 Wi-Fi 和蓝牙；开盖闲置自动睡眠、系统菜单睡眠不创建无线关闭任务，合盖后外接屏继续工作的情况也不触发。

正常恢复需要屏幕实际亮起；合盖来源还需要已经开盖。后台 DarkWake 不触发恢复。关机或重启后通过登录项恢复，因此不保证登录前联网。

两项无线分别保存恢复进度、分别重试，一个失败不会阻止另一个。自动恢复会打开 Wi-Fi 和蓝牙，包括操作前原本关闭的设备；电源操作失败回滚时则尽量还原原始开关状态。

关闭总开关后不创建新的关闭任务，但会继续完成本工具已经创建的恢复任务。菜单中的“恢复 Wi-Fi 和蓝牙”可用于手动重试。

恢复通知只表示设备开关已打开，不表示 Wi-Fi 已联网或蓝牙设备已连接。它使用本地无声通知，拒绝通知权限不影响恢复。

## 环境与构建

- macOS 13 或更新版本。
- Swift 5.9 或更新版本及 Xcode Command Line Tools。
- 使用 Swift 和系统框架，无第三方包依赖。

在项目目录执行：

```bash
./scripts/build_app.sh
```

构建结果位于 `dist/CloseTargetApp.app`。安装到固定位置后启动，按系统提示允许必要的蓝牙、通知或自动化权限。

构建脚本复用稳定的代码签名身份，缺少证书时会停止。其他 Mac 可以显式指定自己的证书：

```bash
CLOSE_TARGET_APP_SIGNING_IDENTITY="你的代码签名证书名称" ./scripts/build_app.sh
```

更新时保持同一证书、Bundle ID `com.local.CloseTargetApp` 和安装位置，以维持现有权限。

## 配置与兼容性

设置保存在本机，待恢复状态位于 `~/Library/Application Support/CloseTargetApp/wifi-recovery.json`。工具通过系统事件监听运行，空闲时不常驻轮询。

Wi-Fi 使用 CoreWLAN；蓝牙电源控制使用与 blueutil 同类的非公开 IOBluetooth 接口。macOS 升级可能影响兼容性，失败时会显示状态并保留恢复入口。

## 常见问题

**按钮没有继续执行电源动作？** 某个目标应用可能未在等待时间内退出。本次动作会取消，可以检查应用名单和等待时间后重试。

**无线没有自动恢复？** 先确认已经正常亮屏；重启后需进入用户会话。再通过菜单的恢复入口重试，并检查权限。

**合盖没有关闭无线？** 合盖外接显示器继续工作时不会触发，普通系统睡眠也不会创建该任务。

**如何更换图标？** 替换 [AppIcon-source.png](Resources/AppIcon-source.png)，运行 `./scripts/generate_app_icon.sh` 后重新构建。
