# CloseTargetApp

一个给自己 MacBook 用的菜单栏小工具：在菜单栏放一个按钮，点击后可以选择睡眠、关机或重启。执行这些动作前，App 会先关闭配置好的目标应用。

## 功能

- 菜单栏按钮
- 自定义 App 图标
- 睡眠、关机、重启快捷入口
- 执行电源动作前强制退出指定应用，并确认全部退出后再继续
- 设置窗口中添加/移除目标应用
- 开机自启动开关
- 可在设置中调整关闭目标应用的最长等待时间（1–60 秒，默认 5 秒），应用提前退出则立即继续
- 本软件的睡眠、关机、重启操作前关闭 Wi-Fi，正常亮屏唤醒或重新登录后打开
- Wi-Fi 恢复记录原子落盘，失败时保留“恢复 Wi-Fi”菜单入口
- 自动保存配置

## Wi-Fi 与等待设置

设置中的 Wi-Fi 功能默认开启，只作用于本软件的三个电源按钮，不接管直接合盖或系统菜单。
流程为：强制退出目标应用 → 等待全部退出 → 保存恢复记录 → 关闭并确认 Wi-Fi → 发送电源请求。
关闭应用超时或 Wi-Fi 关闭失败都会取消本次按钮操作。等待秒数是上限，并非每次固定等待。

睡眠后的恢复需要屏幕唤醒事件和亮屏状态同时满足，后台 DarkWake 不会打开 Wi-Fi。
关机或重启后，通过现有登录项在用户登录后恢复；不保证登录前联网。启用功能时会注册登录项，
若系统要求允许，需要在“系统设置 > 通用 > 登录项”中允许后才能通过本软件执行带 Wi-Fi 管理的关机或重启。

电源请求明确失败会还原操作前的 Wi-Fi 状态；请求发出后应用仍运行且 30 秒未观察到睡眠，也会尝试还原。
若关机取消时本软件已被系统结束，恢复将在再次启动本软件或下次登录时进行。
正常完成电源动作后按配置打开 Wi-Fi，即使操作前原本关闭；普通启动且没有待恢复记录时不改变网络。
打开 Wi-Fi 不等于立即连上网络，关联已保存网络仍由 macOS 处理。

空闲时仅监听系统事件，不扫描网络、不使用常驻计时器。退出等待仅在操作期间每 250ms 检查；
Wi-Fi 状态确认和恢复重试均有次数上限。恢复记录存放于 `~/Library/Application Support/CloseTargetApp/wifi-recovery.json`。

Wi-Fi 使用公开 CoreWLAN API，不通过界面自动化切换。系统策略可能要求首次管理员授权，
保留签名能够保持原有应用身份，但不能替代新增能力本身所需的权限。

## 图标

如果之后想替换 App 图标，可以替换 `Resources/AppIcon-source.png`，然后执行：

```bash
./scripts/generate_app_icon.sh
./scripts/build_app.sh
```

## 打包

```bash
chmod +x scripts/build_app.sh
./scripts/build_app.sh
```

打包完成后会生成：

```text
dist/CloseTargetApp.app
```

建议把它移动到 `/Applications` 后再开启「开机自启动」，这样 macOS 的登录项注册更稳定。

构建脚本会固定复用本机已有的长期代码签名身份，使重新构建后的 App 保持相同代码身份，
避免系统权限随每次编译产生的新二进制失效。如果在其他机器构建，需要通过
`CLOSE_TARGET_APP_SIGNING_IDENTITY` 指定该机器上的稳定代码签名身份。
本机继续使用 `com.local.CloseTargetApp` 和原有证书，不改 Bundle ID、不使用 ad-hoc 签名，也不重置系统权限。

## 使用

1. 打开 `dist/CloseTargetApp.app`。
2. 在菜单栏点击 `xmark.octagon` 图标。
3. 进入「设置...」，添加你想关闭的应用。
4. 回到菜单栏，点击「睡眠」「关机」或「重启」。
5. App 会先强制退出目标应用；确认全部退出后，才执行你选择的电源动作。
6. 如果需要，打开「开机自启动」。

## 测试建议

不需要把整个项目本地跑起来调试。可以按下面几步手动验收：

1. 执行打包脚本，确认生成 `dist/CloseTargetApp.app`。
2. 打开 App 后确认菜单栏出现按钮，Dock 中不出现常驻图标。
3. 在设置里添加一个无重要数据的测试应用，例如「备忘录」或「预览」。
4. 保存当前工作后，点击「睡眠」验证测试应用收到退出请求，电脑进入睡眠。
5. 关机和重启会真实执行系统动作，建议只在确认没有未保存内容时测试。
6. 切换「开机自启动」，若提示需要允许，到系统设置的登录项中确认状态。
